# RIFT 1.3.0 Release Candidate

Date: 2026-08-22

## Scope

This release candidate makes RIFT's model picker evidence-aware and makes the
source tree auditable for an open-source release. RIFT can combine bounded Hub
metadata, explicitly trusted published benchmark snapshots, exact artifact
fit, backend compatibility, and permissioned local finalist measurements.

## Evidence Contract

- `PUBLISHED`: signed external benchmark evidence with retained provenance.
- `ESTIMATED`: model-card, Hub, hardware, artifact, and backend metadata.
- `MEASURED_LOCAL`: RIFT-run benchmark for a matching local artifact/backend.
- `BLOCKED`: unsupported, unverified, unauthorized, or budget-exhausted work.

`rift model recommend` performs no download, install, or launch. `rift model recommend
--verify` verifies one finalist by default and requires explicit permissions.
Use `--verify-top N` and `--verify-budget SECONDS` only when the operator has
accepted the cost.

## Hardware Simulation

Recommendation can be evaluated against a hypothetical workstation without
using the local machine's capacity:

```powershell
rift model recommend --task chat --simulate-hardware "gpu=RTX 5090,vram_gb=32,ram_gb=64,disk_free_gb=500,os=linux"
```

The simulator accepts comma-separated `key=value` pairs or a JSON profile file.
It requires GPU, VRAM, host RAM, and free disk inputs; optional free-memory,
compute-capability, CPU, platform, and storage fields refine the estimate.
Results are marked `profile_kind=simulated`, include assumptions, and reject
pull, install, launch, and local verification side effects.

## Release Audit Boundary

Run:

```powershell
python scripts/audit_release.py --root . --json
```

The audit is a repository hygiene and provenance gate. It does not determine
whether a model, dataset, benchmark, or backend is legally suitable for a
particular deployment. Those obligations remain with the operator and are
documented in `docs/legal/`.

## Known Gates

- No universal accuracy claim is made from mixed leaderboards.
- The local tournament remains intentionally bounded and expensive; published
  evidence is the default quality signal.
- vLLM, SGLang, MLX-LM, physical cluster routing, Android deployment, packaged
  dashboard installers, and GPU/native acceptance remain platform-specific
  gates.
- The archival tag `archive/native-android-2026-08-22` preserves the removed
  native and Android experiments; the release branch contains only the
  pure-Python control plane and canonical UI.
